# Pulse Courier

A separately built Haskell game that depends on the **Unholy library**. The
regular Unholy editor also compiles and registers this same game module.
The engine library has no dependency on the sample.

From the repository root:

```sh
cabal build pulse-courier
cabal run pulse-courier -- projects/pulse-courier/project.hj.json
cabal run pulse-courier -- --play projects/pulse-courier/project.hj.json
cabal run pulse-courier -- --build projects/pulse-courier/project.hj.json
cabal test pulse-courier-tests --test-show-details=direct
```

Or run `make app`, open Unholy, choose **Load → pulse-courier**, and **Play**.
Roll through all three orange cores and deliver to the green portal. **WASD** /
arrows move, **Space** jumps, **E** dashes (with a cooldown), **R** resets, and
**M** mutes. The purple shuttles move using kinematic Bullet bodies.

[PulseCourier.hs](src/PulseCourier.hs) defines the scene using `spawnMesh`,
`Transform`, `Material` and `Body`. Its `Session` contains typed `Relay`, `Mover`
and `Courier` components, using `Unholy.ECS.Components`. Before-physics systems
control the ball and animate relays/platforms; after-physics systems receive
real Bullet trigger events, remove collected entities, score and finish.
Typed effects send audio, HUD text and teleport requests to engine resources.
It uses no Lua scripts.

The saved scene stays editable: initialization discovers entities in that
scene and retains edits. `Courier` needs a dynamic sphere body; `Exit sensor`
needs a trigger. Relays and shuttles are discovered by name prefixes. The game
currently expects three relays. Custom components are runtime state, not
serialized inspector fields. Stop discards that state; Play creates it again.

To regenerate the original scene after editing a **copy** of it:

```sh
cabal run pulse-courier -- --write-scene /path/to/copied-project
```

This writes the scene file; copy `projects/pulse-courier/assets/` too. The sample
reuses the original procedurally generated Marble Run sounds (the pickup sound
is its checkpoint chime). All geometry is generated by the Haskell renderer.

Haskell source changes require `cabal build` / `make app`; compiled games are
registered with `runApplication [pulseCourier]`. Loading a project does not
compile arbitrary source files or dynamically load plugins. Export copies the
current executable, so its game registrations travel with the player. Lua
remains available for live script iteration.
